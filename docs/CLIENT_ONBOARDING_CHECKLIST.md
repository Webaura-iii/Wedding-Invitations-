# Webaura Client Onboarding Checklist

Use this checklist for every paid wedding invitation. Do not publish the sample configuration as a real couple's invitation.

## 1. Collect and confirm

- [ ] Couple's preferred display names in English, Urdu, and Arabic (ask the couple for their preferred spellings/transliterations).
- [ ] Parent/family names in all requested languages, or confirmation that they should be omitted.
- [ ] Name order and wax-seal initials.
- [ ] Ceremony name, date, start time, duration, and IANA timezone.
- [ ] Venue name, complete address, city/country, and verified map search.
- [ ] Dress code and optional closing message/dua.
- [ ] Approved photos/assets, if any, with confirmation that Webaura may publish them.
- [ ] Correct spelling, religious wording, date, and location approved by the couple.

## 2. Configure and review

- [ ] Create a unique, readable slug and check for collisions.
- [ ] Populate every editable field for English, Urdu, and Arabic.
- [ ] Check Urdu and Arabic direction, punctuation, font rendering, and line breaks on mobile.
- [ ] Confirm the wax seal initials and both names are correct.
- [ ] Check event date against the countdown and calendar export.
- [ ] Open the map link and verify it points to the correct venue.
- [ ] Review keyboard navigation, reduced-motion behavior, and sound control.
- [ ] Send the preview to the couple and record their approval before publishing.

## 3. Publish and hand over

- [ ] Publish the invitation and test the final URL in a private/incognito window.
- [ ] Test on a second device/browser to ensure content is not dependent on localStorage.
- [ ] Test the shared link in a messaging app and verify title/description/preview image.
- [ ] Confirm guests cannot see the editor or draft content.
- [ ] Give the couple the final URL and a contact path for corrections.
- [ ] Record the agreed hosting duration, correction window, renewal/expiry policy, and deletion process.
- [ ] Keep only the minimum client information needed to deliver the service.

## 4. Change requests and unpublishing

- [ ] Verify the requester is authorized before changing names, date, venue, or photos.
- [ ] Preview and recheck all three languages after edits.
- [ ] If the event is postponed or the URL must be withdrawn, unpublish promptly and verify public access is blocked.
- [ ] On cancellation or expiry, follow the agreed retention/deletion policy and remove uploaded assets where appropriate.
